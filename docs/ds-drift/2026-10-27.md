## Interpretation

This is the upstream MUI template, so drift here is a style choice by its authors, not agent error. Imports and API fidelity are clean: every component and prop exists in @mui/material 9.5.0. All 29 findings are review level.

- Token discipline (26 findings) is nearly all raw sx values: string pixel and rem sizes ('8px', '1rem', '1.5rem', '24px') where the theme spacing scale and typography variants already cover them. AppNavbar.tsx and SelectContent.tsx carry 14 of them. p: '8px' is theme.spacing(1), and fontSize: '1rem' repeats body1. The one raw color, the inset rgba boxShadow in AppNavbar.tsx, has no matching token in themePrimitives.ts.
- Some are expected: '1px solid' borders pick up their color from theme.palette.divider, and --template-frame-height is a layout variable, not a token.
- Accessibility (3 findings) is mostly noise. SelectContent.tsx already sets inputProps aria-label. MenuButton.tsx and ColorModeSelect.tsx are wrappers that forward props, so the label comes from callers. The real gap the scanner points at is a caller: SideMenuMobile.tsx renders <MenuButton showBadge> with no aria-label.

Fix first:
- Add aria-label="Open notifications" to the MenuButton in SideMenuMobile.tsx.
- Replace string px/rem in AppNavbar.tsx and SelectContent.tsx with spacing numbers (p: 1, gap: 1) and typography variants.
- Move the AppNavbar boxShadow into themePrimitives.ts as a named shadow.

The three a11y findings on prop-forwarding wrappers are known noise for this repo; no config field targets them, so expect them on every run until the wrappers set a default label.
